Architecture, technology and data integrity

The interfaces use HTML, CSS and JavaScript. Pure rule modules handle coding, monetary allocations, invoice matching, command replay and analytical projections. Views in the connected story reuse the same journal. The management snapshot, dated cohort and source-document inbox declare their own contexts rather than silently joining records.

Machine observations are deterministic fictional fixtures with unit, quality, UTC time and asset identity. Curation retains a reasoned exclusion ledger. State intervals partition the replay window. A reviewed maintenance case links to purchasing through a stable request ID; the BI model uses declared fact grains and integer cents.

Native links, responsive layouts, keyboard controls and progressive disclosures make the experience inspectable. Automated rule and browser checks run in CI. The browser report is not embedded Power BI, and this portfolio does not need live employer systems, credentials or paid connectors.

What is implemented, and where the demonstration stops

Implemented: governed requisitions, simulated purchasing approval/PO, receipt checks, single/multi-line invoices, connected CSV batch staging, owned exceptions, reviewed supplier corrections, posting, separate authorization/settlement, browser BI, management snapshots, dated financial trends and invoice aging, executed supported-text and bounded UBL XML extraction with source fingerprints, field lineage and retained text-format invoice revisions, machine replay, maintenance review, idempotent purchasing handoff, recorded work and independent completion verification.

Outside these scenarios: live equipment control, authenticated production roles, PDF/image/email OCR, general-ledger completeness, tax/credits/FX, native Power BI authoring and automatic proof of maintenance completion. These boundaries do not prevent the complete simulated journeys described above.
