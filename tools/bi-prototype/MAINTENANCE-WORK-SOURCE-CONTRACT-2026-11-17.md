# Maintenance and work saved-source ownership

This bounded controller change protects the existing fictional browser journals. It does not introduce enterprise authentication, cross-user transactions or live equipment/system connections. Existing maintenance/work rules, source observations, policy, journal schemas, business dates, financial calculations and workflow responsibilities are unchanged.

- The maintenance editor retains the exact saved value loaded on entry. Review writes and imports reject a different saved value, including changed commands at the same revision, a deleted key, or empty/malformed replacement data. Download the visible checkpoint if needed, then reload the page to use newer maintenance progress.
- A purchasing handoff checks both its loaded maintenance value and the purchasing value refreshed for that action before writing either journal. Successful writes advance both saved baselines. A failed second write uses the existing rollback to restore prior values; in-memory states/baselines advance only after both saves succeed. An unconfirmed rollback still reports that reloading is required.
- Maintenance and work checkpoint imports check their owned source before asynchronous reading, after decoding/replay, and after any replacement confirmation. Confirmed valid recovery of an unchanged damaged source remains supported. File inputs reset after completion so the same file can be selected again after cancellation, rejection or recovery.
- Work commands check the exact saved work value before decisions and again in their shared save path. Successful load, save, import and coherent example replacement update that baseline. Explicit refresh reads newer work and linked context without changing saved journals. Downloads of the valid visible checkpoint retain the prior in-memory version when a stale write is blocked.
- The material-ready work example requires confirmation if any saved key exists, including an empty string. Immediately before its grouped write, all three saved values must still equal those captured before confirmation. A changed/deleted/damaged key blocks the whole replacement. Existing grouped rollback preserves prior missing keys on tested second/third-write failures; no new completion, invoice or payment is fabricated by the example.

Verification: `node tools/test-bi-maintenance-work-source.mjs` covers 23 integrity/recovery groups and eight responsive automated accessibility screens per engine. Run with the existing Chromium/Firefox/WebKit selector. Existing machine and work browser suites additionally verify maintenance-to-purchasing/payment/report lineage and execution, return/rework and independent completion verification. Failed read/write tests exercise unavailable browser storage without treating it as an account quota or permission diagnosis. These checks do not establish a comprehensive whole-site audit or production multi-user concurrency guarantees.
