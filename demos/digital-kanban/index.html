    System architecture

    A small workflow with deliberate controls.

    The implementation pattern separates stock-point configuration, item definitions, stock-point/item relationships, requests, and restocker access so the experience stays simple without hiding the operating rules.

    01 / route

    Direct or storefront

    A QR can identify one item for immediate action or a small set of items at a shared stock point.

    02 / duplicate

    One open signal

    The item and request type form a controlled key; a second scan shows status instead of creating duplicate work.

    03 / snapshot

    History stays readable

    Item, stock-point, and location labels are snapshotted on the request so later configuration changes do not erase context.

    04 / close

    Refill is explicit

    The restocker completes the request, clears the open key, and leaves a traceable closeout event.

    Synthetic recreation. No information is submitted, stored, or connected to employer systems.
