    OT-to-decision architecture

    Connectivity is only the first layer.

    The differentiator is the defined context between a machine signal and a business response: identity, state logic, time, product, reason, ownership, and history.

    01 / identity

    Asset context

    Every tag or event belongs to a stable asset, production area, and operating hierarchy.

    02 / semantics

    State and reason model

    Run, idle, blocked, starved, planned, and fault states need controlled definitions.

    03 / time

    Event integrity

    Timestamps, duration, late data, gaps, and clock alignment determine whether metrics are trustworthy.

    04 / action

    Human operating loop

    Alerts should route a defined exception to an owner—not create noise or bypass judgment.
